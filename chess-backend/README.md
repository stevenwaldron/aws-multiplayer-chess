# Chess backend — API Gateway WebSocket + Lambda + DynamoDB

## Structure

```
chess-backend/
├── shared-src/            Source of truth for shared Lambda code
│   ├── dynamo.js          All DynamoDB reads/writes
│   ├── chessLogic.js      chess.js wrapper (move validation, ownership checks)
│   ├── codeGenerator.js   Game code + player token generation
│   └── wsResponse.js      postToConnection helper
├── layer/nodejs/          Lambda layer build target (package.json only —
│                          node_modules is generated by Terraform on apply)
├── functions/
│   ├── onConnect/
│   ├── onDisconnect/
│   ├── handleGameSetup/   handles create / join / reconnect
│   └── handleMove/
├── infra/                 Terraform
└── test/mockHandleMove.js Local test harness (mocked DynamoDB, no AWS needed)
```

Each function's `index.js` requires shared code as `require('shared/dynamo')`
etc. — this resolves via the Lambda layer, which is mounted at `/opt/nodejs`
and automatically added to `NODE_PATH` for the Node.js runtime.

## Deploying

Prerequisites: Terraform >= 1.7, an AWS account with credentials configured
(`aws configure` or equivalent), Node.js for the layer build step.

```
cd infra
terraform init
terraform plan
terraform apply
```

`terraform apply` runs `npm install` and copies `shared-src/` into the layer
automatically (see the `null_resource.build_layer` provisioner in
`lambda.tf`) — you don't need to build the layer by hand.

The `websocket_url` output is what the frontend's WebSocket client connects
to.

### One-time state backend setup (optional)

`main.tf` has a commented-out S3 backend block. If you want remote state
instead of a local `terraform.tfstate` file, create an S3 bucket and a
DynamoDB table for locking first, then uncomment that block with your
bucket/table names.

## WebSocket message contract

All messages are JSON with an `action` field — this is what API Gateway's
`route_selection_expression` uses to pick a route.

### Client → server

```jsonc
// Create a new game
{ "action": "create" }

// Create a single-player game against the CPU (starts immediately, no
// waiting for an opponent). difficulty: "easy" | "medium" | "hard", defaults to "medium"
{ "action": "create_vs_cpu", "difficulty": "medium" }

// Join an existing game
{ "action": "join", "game_id": "swift-falcon-42" }

// Reconnect to a game you're already in (after a refresh/dropped connection)
{ "action": "reconnect", "game_id": "swift-falcon-42", "player_token": "..." }

// Make a move
{ "action": "move", "from": "e2", "to": "e4", "promotion": "q" } // promotion optional, defaults to queen
```

### Server → client

```jsonc
// Response to create
{ "type": "created", "game_id": "...", "player_token": "...", "color": "white" }

// Response to join, sent to the joiner
{ "type": "joined", "game_id": "...", "player_token": "...", "color": "black", "board_state": "<FEN>", "turn": "white" }

// Sent to the creator when someone joins
{ "type": "game_started", "game_id": "...", "board_state": "<FEN>", "turn": "white" }

// Response to create_vs_cpu — the game starts immediately
{ "type": "cpu_game_started", "game_id": "...", "player_token": "...", "color": "white", "board_state": "<FEN>", "turn": "white", "difficulty": "medium" }

// Response to reconnect
{ "type": "reconnected", "game_id": "...", "color": "white", "board_state": "<FEN>", "turn": "white", "status": "in_progress", "move_history": [...], "is_cpu_game": false }

// Sent to both players after a legal move (or, in a vs-CPU game, sent twice
// in a row to the human — once for their move, once for the CPU's automatic
// response computed in the same Lambda invocation)
{ "type": "move_made", "game_id": "...", "from": "e2", "to": "e4", "san": "e4", "board_state": "<FEN>", "turn": "black", "status": "in_progress" }

// Any failure
{ "type": "error", "error": "not_your_turn" }
// error values: not_found | expired | already_full | invalid_token |
// not_in_a_game | game_not_active | not_your_turn | not_your_piece |
// illegal_move | move_conflict | unknown_action | server_error
```

## Testing without AWS

`test/mockHandleMove.js` exercises `handleMove`'s full logic (turn
enforcement, ownership checks, the conditional-write path) against a mocked
DynamoDB — no AWS credentials needed:

```
node test/mockHandleMove.js
```
